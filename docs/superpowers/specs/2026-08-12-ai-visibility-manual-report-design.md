# Отчёт о цитируемости из браузерного прохода

**Дата:** 2026-08-12
**Статус:** согласовано, готово к планированию
**Развивает:** `docs/superpowers/specs/2026-08-12-ai-visibility-telegram-report-design.md`

## Задача

Отчёт в Telegram сейчас собирается только из свипа Gemini. Автоматический слой
выключен по решению владельца: за 18 вызовов он дал одно попадание из девяти,
тогда как один браузерный проход по ChatGPT и Perplexity показал, что ChatGPT
отрицает существование нашего продукта и цитирует Goodfirms вместо нас.

**Цель:** тот же отчёт с теми же советами, но собранный из ручного прохода по
движкам, у которых нет бесплатного API.

## Решения, принятые до проектирования

| Вопрос | Решение | Почему |
|---|---|---|
| Что записывает проход | Статус и список процитированных доменов | Без доменов работают два правила из пяти; с ними — все, включая самое ценное «страница есть, а цитируют вот этих» |
| Как подавать два движка | Одно сообщение, цифры по каждому | На одном и том же брендовом запросе Perplexity поставил нас первым источником, а ChatGPT не процитировал вовсе. Усреднение стёрло бы ровно это |

## Данные

`docs/seo/ai-visibility/manual/YYYY-MM.json` — по записи на пару «движок ×
промпт». К трём полям, которые там уже есть, добавляются два:

```json
{
  "engine": "chatgpt",
  "id": "pl-ksiegowosc-wfirma",
  "status": "absent",
  "citedDomains": [],
  "sourceDomains": ["wfirma.pl"],
  "note": "Заявил, что готового ассистента к wFirma не существует"
}
```

`citedDomains` — наши домены среди источников, `sourceDomains` — все. Это ровно
те имена полей, которые правила уже читают у автоматического прогона, поэтому
переходнику не нужно ничего переименовывать.

Существующий `manual/2026-08.json` этих полей не имеет: он писался до решения.
Файл дополняется вручную при следующем проходе, а переходник обязан выдерживать
запись без них — считать её как пустые списки, а не падать.

Поля `crawlers` и `referrals` в том же файле к отчёту отношения не имеют и
переходником игнорируются.

## Архитектура

Новый модуль `scripts/ai-visibility/manual.mjs`, чистый:

- `manualToRuns(manual, config) -> Array<{ engine, run }>`

Каждый `run` имеет ту же форму, что и закрытый свип, — `{ date, results,
summary }` — поэтому `buildAdvice` и правила используются без единой правки.
`lang`, `kind` и `target` подтягиваются из `config.prompts` по `id`; сводка
считается существующей `summarize` из `analyze.mjs`. Каждый результат получает
одну попытку, несущую `citedDomains` и `sourceDomains`.

Движки в выдаче отсортированы по имени — отчёт должен быть детерминированным.

Рендер получает отдельную функцию `renderManualReport(month, perEngine)` в
`report.mjs`, где `perEngine` — массив `{ engine, run, advice }`. Втискивать
двухдвижковую форму в `renderTelegramReport` значило бы испортить обе.

## Доставка

Новый workflow `.github/workflows/ai-visibility-manual.yml` — **только
`workflow_dispatch`, без cron**, с обязательным входом `month`. Он читает
закоммиченный файл месяца, рендерит сообщение в вывод шага и отправляет его тем
же шагом Telegram, что и основной workflow: та же проверка отсутствующих
секретов, та же ветка `🔴` по статусу джоба.

Токен бота остаётся секретом GitHub. Ни скрипт, ни человек, запускающий проход,
его не видят.

`GEMINI_API_KEY` этому пути не нужен вовсе.

## Сообщение

```
📊 AI-видимость mi-code.pl
Ручной проход · 2026-08 · ChatGPT, Perplexity

ChatGPT: 0 из 3
Perplexity: 1 из 1

Цитируют вместо нас: goodfirms.co (2) · rejestr.io (1)

Что делать:
• ChatGPT · «Czy istnieje asystent AI, ktory laczy sie z wFirma…»:
  страница под запрос есть (/products/accounting-ai/), но цитируют wfirma.pl
• ChatGPT · Бренд называют, но не ссылаются:
  «Czym zajmuje sie MiCode Sp. z o.o. z Gdanska?» — это ссылки, а не индексация
```

Советы помечены движком, потому что один и тот же промпт даёт разные советы у
разных движков, и без пометки читатель не поймёт, к чему относится строка.

Строка «Цитируют вместо нас» считается **по всем движкам сразу**, а не по
каждому: это сводка «кто занимает наши запросы», и разбивать её по движкам
значило бы утроить строку ради различия, которое здесь не важно. Советы, в
отличие от неё, остаются подвижковыми.

Цифры в примере — реальные, из `manual/2026-08.json` за первый проход.

Ограничение Telegram в 4096 символов и правило «урезается только хвост советов»
переносятся без изменений.

## Обработка краёв

| Ситуация | Поведение |
|---|---|
| Запись ссылается на `id`, которого нет в `prompts.json` | запись пропускается, в лог идёт предупреждение с этим `id` |
| Запись без `citedDomains` / `sourceDomains` | считается как пустые списки |
| В файле один движок | отчёт с одной строкой цифр, без пометок движка в советах |
| Файл месяца отсутствует | джоб падает с внятным сообщением, а не шлёт пустой отчёт |
| Ни одного правила не сработало | блок «Что делать» опускается целиком |

## Тесты

`scripts/ai-visibility/manual.test.mjs`: форма выдачи переходника; подтягивание
`lang`/`kind`/`target` из конфига; запись с неизвестным `id` пропускается;
запись без новых полей не роняет; движки отсортированы; сводка совпадает с той,
что даёт `summarize` на тех же данных.

В `report.test.mjs`: отчёт по двум движкам содержит обе строки цифр; советы
помечены движком; при одном движке пометок нет; лимит Telegram соблюдается и
урезается только хвост советов.

## Чего это не делает

Два правила из пяти на ручных данных почти не сработают: «на грани» требует
повторов, которых в браузерном проходе нет, а «перекос портфеля» — минимум трёх
цитат, что при выборке в шесть запросов маловероятно. Остаются три рабочих
правила, и это те, что уже дали смысл на живых данных.

Автоматический слой Gemini не удаляется. Он написан, покрыт тестами и выключен
одной командой; `npm run ai-visibility` продолжает работать локально. Удалять
рабочий код, который может понадобиться, хуже, чем оставить выключенный
workflow.

Этот путь не автоматизируется в принципе: браузерный проход ведёт человек или
Claude. Отчёт приходит тогда, когда проход сделан, — раз в месяц по ритуалу из
`docs/seo/ai-visibility/README.md`, а не по расписанию.
