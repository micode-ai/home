# Маркетинговая фабрика для mi-code.pl

**Дата:** 2026-07-31
**Статус:** согласовано, готово к планированию

## Задача

Построить в репозитории сайта повторяемое производство рекламных материалов —
по образцу `ai-budget-assistant/docs/marketing`, но перенастроенное с B2C на B2B.

**Цель:** лиды на услуги разработки и AI-интеграции.
**Аудитория:** CTO, владельцы бизнеса и маркетинг-директора в Польше.
**Языки:** польский (основной рынок), английский (LinkedIn, зарубежные лиды).
**Каналы:** LinkedIn (карусель + одиночный пост), Facebook/Instagram фид 4:5,
Reels/Stories 9:16, OG-карточки для шаринга ссылок.

### Чем это отличается от фабрики приложения

Фабрика AI Budget Assistant заточена под B2C: вертикальные reels и сторис.
Для B2B-лидов это слабый канал — решения о заказе разработки принимают в
LinkedIn, где работают карусели, кейсы с цифрами и разборы «до/после».
Поэтому холсты и типы слайдов проектируются заново, а не переиспользуются.

## Контент-стратегия

Воронка из двух треков плюс общий низ. Кампания на услуги в первую фазу не
входит: в `services.json` сейчас три общие формулировки без цен и сроков,
рекламировать нечего. Возвращаемся к ней, когда появятся продуктизированные
офферы.

| Уровень | Трек | Материал | Ведёт на |
|---|---|---|---|
| Верх | боль и экспертиза | 5 каруселей из статей блога | статью |
| Середина | продукт как доказательство | 6 постов по продуктам | страницу продукта |
| Низ | оффер и CTA | переиспользуемый финальный слайд | форму контакта |

### Верх воронки — 5 кампаний

Каждая — выжимка уже написанной статьи. Подача: вопрос, который у заказчика
уже в голове, а не рассказ о нас.

| id кампании | Крючок | Источник | Аудитория |
|---|---|---|---|
| `cost-of-ai-agent` | Сколько реально стоит AI-агент в месяц | `ai-agent-cost-per-month-model` | CFO, CTO |
| `rag-without-hallucinations` | Почему бот врёт и как научить его говорить «не знаю» | `legalka-kb-ai-architecture` | CTO, юр. и мед. отрасли |
| `geo-aeo` | Вас не видно в ChatGPT: что такое GEO и AEO | `geo-aeo-generative-answer-engine-optimization` | маркетинг-директора |
| `accounting-automation-pl` | Что в польской бухгалтерии реально отдать AI | `accounting-ai-agent-architecture` | владельцы бизнеса в PL |
| `self-improving-agents` | Команды агентов, которые учатся во сне | `self-improving-agent-teams` | tech-лиды |

### Середина воронки — 6 кампаний

По одной на продукт: `accounting-ai`, `legalka-kb`, `emarketing-ai`,
`budget-assistant`, `testing-ai`, `ngx-chat`.

Подача не «купите продукт», а «мы это построили — построим и вам»:
бизнес-боль → что построили → архитектура (LangGraph-диаграмма со страницы
продукта) → цифры → CTA на mi-code.pl.

Итого 11 кампаний × 2 языка × 5 форматов ≈ 110 рендеров.

## Архитектура генераторов

### `brand.py` — единственный источник визуальных токенов

Токены берутся **с сайта** (`src/app.css`), не из фабрики приложения. Креатив и
лендинг, на который человек попадает по клику, должны выглядеть одной компанией.

| Токен | Значение | Источник |
|---|---|---|
| navy | `#1E40AF` | `--color-primary` |
| navy dark | `#1E3A8A` | `--color-primary-dark` |
| orange | `#F97316` | `--color-accent` |
| orange light | `#FB923C` | `--color-accent-light` |
| тёмная база | `#0F172A` | `--color-bg-hero` |
| текст на светлом | `#1E293B` | `--color-text-primary` |
| граница | `#E2E8F0` | `--color-border` |
| заголовки | Poppins | `--font-heading` |
| текст | Open Sans | `--font-body` |

Модуль отдаёт: палитру, загруженные шрифты, бейдж MICODE, safe-зоны под UI
соцсетей и примитивы — скруглённая карточка, «браузерная рамка» вокруг
скриншота, пилюля-тег, футер с доменом.

Шрифты кладём файлами в `assets/fonts/`. В фабрике приложения зашит путь
`C:/Windows/Fonts/segoeuib.ttf`, из-за чего рендер не воспроизводится ни на
macOS, ни на раннере CI. Poppins и Open Sans распространяются под открытыми
лицензиями, допускающими хранение в репозитории — сборка станет одинаковой
везде. Точные файлы лицензий кладём рядом со шрифтами.

### `campaign.json` — спека кампании

Генераторы читают спеку и ничего не хардкодят. Добавить кампанию = добавить
JSON, а не написать ещё один скрипт. Это та же логика, по которой на сайте
`products.json` управляет страницами продуктов вместо захардкоженной разметки.

```jsonc
{
  "id": "cost-of-ai-agent",
  "track": "funnel-top",
  "target": "https://mi-code.pl/blog/ai-agent-cost-per-month-model/",
  "utm": { "campaign": "cost-of-ai-agent" },
  "slides": [
    { "type": "hook",    "bigNumber": "≈ 340 zł",
      "pl": { "eyebrow": "...", "headline": "...", "sub": "..." },
      "en": { "eyebrow": "...", "headline": "...", "sub": "..." } },
    { "type": "problem", "pl": {...}, "en": {...} },
    { "type": "diagram", "asset": "src/cost-model.png", "pl": {...}, "en": {...} },
    { "type": "numbers", "rows": [...], "pl": {...}, "en": {...} },
    { "type": "cta",     "pl": {...}, "en": {...} }
  ]
}
```

Пять типов слайдов: `hook`, `problem`, `diagram`, `numbers`, `cta`. Каждый умеет
рендериться в любой холст — поэтому один JSON даёт и карусель, и пост в фид, и
сторис.

### Генераторы и холсты

| Скрипт | Формат | Размер | Замечание |
|---|---|---|---|
| `build_carousel.py` | LinkedIn-карусель | 1080×1350 × N | отдаёт PNG-серию **и склеенный PDF** — LinkedIn принимает карусели только как документ |
| `build_single.py` | LI 1:1 / фид 4:5 / OG | 1200×627, 1080×1350, 1200×630 | три холста из одной спеки, слайд `hook` или `numbers` |
| `build_reel.py` | Reels / Stories | 1080×1920 | статичные постеры `story-9x16-01..N.png` (по слайду) **и** видео `reel.mp4` + `reel.gif` — проход по тем же слайдам с плавным переходом, 12–15 сек |
| `capture_screens.py` | съёмка исходников | — | страницы сайта в `creatives/<id>/src/` |

Стек: Pillow, imageio, numpy — уже установлены (12.1.1 / 2.37.0 / 2.3.1).

### Съёмка скриншотов

`capture_screens.py` на **Playwright**: поднимает `npm run preview`, ходит по
страницам продуктов и статей, снимает полные страницы, отдельные секции и
отрендеренные LangGraph-диаграммы. Диаграммы рисуются через mermaid в браузере,
статикой их не достать — headless-браузер здесь обязателен, а не удобство.

Playwright — новая зависимость проекта. Принято осознанно: без него обновление
визуала после каждого редизайна становится ручной работой.

### Атрибуция

Все ссылки в `cta-blocks.md` проставляются с UTM:
`?utm_source=linkedin&utm_medium=social&utm_campaign=<id>`.

Раз цель — лиды, без атрибуции через месяц будет непонятно, какая из 11 кампаний
привела заказчика, и вторую фазу не на чем будет строить.

## Объём первой итерации

Каркас плюс одна кампания целиком:

1. `docs/marketing/` со структурой, `README.md`, `strategy.md`, `content-plan.md`
2. `brand.py` + шрифты + бейдж в `assets/`
3. Все четыре генератора
4. `cta-blocks.md` с UTM-схемой
5. Кампания `cost-of-ai-agent`: `campaign.json`, тексты PL/EN, все пять форматов

Так виден реальный результат и дизайн можно поправить до того, как он
растиражирован на 11 кампаний. Остальные 10 — следующая фаза, уже механическая.

## Что считаем успехом

- `python build_carousel.py cost-of-ai-agent pl en` отрабатывает с чистого
  клона и даёт PDF, готовый к загрузке в LinkedIn
- Креатив визуально узнаётся как mi-code.pl: та же палитра, те же шрифты
- Тексты PL/EN готовы к копированию без правок
- Каждая ссылка несёт UTM и ведёт на нужную страницу сайта
- Добавление 12-й кампании не требует нового кода — только `campaign.json`
  и файл в `copy/`

## Границы

- Кампания на услуги (`services.json`) — вне первой фазы, нет офферов
- Русский язык — вне объёма, решено делать PL + EN
- Публикация в соцсети руками, автопостинг не автоматизируем
- Существующая фабрика в `ai-budget-assistant` не трогается и не мигрирует
