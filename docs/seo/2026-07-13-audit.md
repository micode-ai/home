# SEO / GEO Audit — MiCode Sp. z o.o. (mi-code.pl)

**Date:** 2026-07-13
**Stack:** Svelte 5 + Vite multi-page static site (no SvelteKit/Astro/router), SSR-prerendered at build time via `scripts/prerender.mjs` (`svelte/server` render → static HTML per locale), deployed to GitHub Pages via `.github/workflows/deploy.yml`. Canonical domain `https://mi-code.pl`. Trilingual: `pl` (root, default), `en` (`/en/…`), `ru` (`/ru/…`).
**Scope audited:** landing page (`index.html`/`App.svelte`), all 6 product pages, blog listing, all 9 articles, `robots.txt`, `sitemap.xml`, `llms.txt`, `404.html`, prerender pipeline, i18n/locale plumbing.

## Executive summary

- **This is an unusually mature SEO setup for a small studio site** — real per-locale prerendering (not just client-side i18n), reciprocal hreflang, JSON-LD (Organization/ProfessionalService, WebSite, SoftwareApplication, FAQPage, BreadcrumbList, BlogPosting/TechArticle), an `llms.txt`, and a `1200×630` OG image. Most of this audit is about tightening an already-good foundation, not building one from scratch.
- **Biggest win: `public/llms.txt` is stale and actively wrong.** It documents a `?lang=` query-param locale scheme and claims the site *intentionally* omits hreflang — both false; the real site uses `/en/`/`/ru/` path prefixes with full reciprocal hreflang. It's also missing the Legalka KB product and 3 of 9 blog articles entirely. Any AI agent or answer engine reading this file today gets a wrong mental model of the site and would generate broken URLs.
- **Second biggest win: a genuine client-side bug in `SEO.svelte`** — after hydration, the canonical URL and `og:url` on the homepage are unconditionally reset to `https://mi-code.pl/`, even when the visitor (and prerendered HTML) is on `/en/` or `/ru/`. This silently un-does the correct self-referencing canonical that `prerender.mjs` writes into the static HTML, and could tell Google to consolidate `/en/`/`/ru/` into the Polish homepage.
- **Root homepage `<title>`/description exist in two places and disagree** — the static `index.html` copy and `src/data/seo-home.json` (used by both `prerender.mjs` for en/ru and by `SEO.svelte` post-hydration for pl) are different strings. Non-JS crawlers and JS-rendering crawlers will see two different titles for the same Polish homepage.
- `blog/index.html`'s embedded `Blog` JSON-LD only lists 2 of 9 posts in its `blogPost` array (stale since the early build) — low effort to fix or drop.
- Committed `public/sitemap.xml` is currently missing the 2 newest articles (6 URL entries across 3 locales) — production is fine (GitHub Actions rebuilds it on every deploy and the latest deploy succeeded), but the checked-in file drifts stale between deploys, which misleads anyone testing locally or from `git blame`.

## What already looks good (don't touch)

- **Per-locale prerendering is real, not cosmetic.** `scripts/prerender.mjs` server-renders `App`/`ProductPage`/`BlogListing`/`ArticlePage` via `svelte/server` for all 3 locales and writes fully-formed static HTML to `dist/`, `dist/en/`, `dist/ru/` — this is exactly the right architecture for a router-less multi-page Vite site and most competitors doing "fake" client-side i18n don't have this.
- **hreflang is correct and reciprocal** in both the sitemap (`scripts/prerender.mjs:146-153`) and per-page `<head>` (`scripts/prerender.mjs:60-71`), including `x-default` → Polish. Verified against `public/sitemap.xml`.
- **`robots.txt`** allows everything, explicitly welcomes `GPTBot`, `ChatGPT-User`, `ClaudeBot`, `anthropic-ai`, `PerplexityBot`, `Google-Extended`, `CCBot`, and correctly points at the sitemap.
- **JSON-LD coverage is broad and mostly correct**: Organization+ProfessionalService with `PostalAddress`/`geo`/`areaServed`/`founder` (Person with `sameAs`/`alumniOf`), `WebSite`, per-service `Service` nodes, per-product `SoftwareApplication` + `FAQPage` + `BreadcrumbList`, per-article `BlogPosting`/`TechArticle` + `BreadcrumbList` with `author`/`publisher`/`datePublished`/`dateModified`/`inLanguage`. All 6 products have FAQPage schema — a genuine GEO strength most competitors skip.
- **`llms.txt` exists at all** — most companies this size don't have one. The content model (Company/Products/Blog/FAQ) is exactly right; it just needs the staleness/accuracy fixes above.
- **Single `<h1>` per page**, verified across `Hero.svelte`, `ProductPage.svelte`, `ArticlePage.svelte`, `BlogListing.svelte`, `NotFoundApp.svelte` — no duplicates, no skips.
- **404 handling is correct for GitHub Pages**: `404.html` carries `noindex, nofollow` and GH Pages serves it with a genuine HTTP 404 status for unmatched paths.
- **Internal cross-linking exists both directions**: each article has a `relatedProductSlug` linking to its product (`ArticlePage.svelte:150-158`), and each product page shows its `relatedArticle` back (`ProductPage.svelte:194-202`) — including the 2 newest architecture articles, which are correctly wired.
- **`og-image.png` is exactly 1200×630** — correct OG dimensions, verified via PNG header.
- **NAP (name/address/phone-equivalent) is consistent** between visible footer text (`pl.json:290` / `319`), the Organization schema `PostalAddress`, and the contact form — same address, same email, both places.
- Image `alt` text is present and localized (via `imageAltKey`) on all product images; decorative SVG icons are correctly `aria-hidden="true"`.
- `mermaid` is dynamically imported (`await import('mermaid')`) — not in the main bundle, good for JS payload/INP.
